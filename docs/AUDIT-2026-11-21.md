# Repository Audit — 2026-11-21

Scope: current application library, GUI/native boundaries, process ownership,
settings/history, download arguments, installer/scripts, dependency lock and CI.
The starting commit was `27ea2fb` on `main`. This audit fixes concrete defects;
it does not establish that every external extractor or machine configuration works.

## Findings and Changes

| Finding | Change / regression coverage |
|---|---|
| Explicit clipboard requests consumed the listener's global sequence, and failed reads consumed notifications | Manual reads bypass event deduplication; event sequence advances only after a successful read |
| Second-instance URL arguments were discarded | Bounded, acknowledged native URL forwarding to the existing owned executable |
| Recovery hotkey queued intent without waking a hidden GUI | Restore the main window after queuing the show request |
| Failed image fetches/decodes retried every frame; no thumbnail-specific dimensions/allocation budget | Record the attempted URL before launch, clear disconnected workers, reset per popup; decoder limits dimensions to 2048×2048 and allocation to 32 MiB |
| Archive comparisons ignored case in video IDs | Extractor comparison stays case-insensitive; IDs compare exactly |
| Height-capped presets had an unrestricted final fallback | All format alternatives retain the chosen height cap |
| Removed subscriptions could still enqueue in-flight results with the default preset | Look up the current subscription before recording or enqueuing; use its current preset |
| Playlist parser accepted `httpx:` and malformed `http:` URLs | Reuse HTTP(S) URL validation, with nonempty host and no control/space bytes |
| Queued/paused cancellations bypassed the recent-job bound | Every cancellation path retains at most the latest 50 completed/cancelled jobs |
| Disk queries failed for not-yet-created destinations | Query the nearest existing directory; retain unknown results honestly |
| Native early-return and COM lifetime paths leaked resources | Close duplicate mutex handles, signal the event waiter on platform drop and close its event when the loop ends; resolve startup paths before opening registry state; release COM references and balance owned apartment initialization |
| rustix 1.1.5 matched RUSTSEC-2026-0486 | Isolated patch update to 1.1.6 |

## Dependency Resolution

`cargo update -p rustix@1.1.5 --precise 1.1.6` generated the lockfile.
Only rustix changed package version/checksum. Cargo also reselected existing
`windows-sys` edges within broad declared requirements for arboard, dirs-sys,
errno, tempfile, uds_windows and wait-timeout. These are resolver-produced
changes, not manual lockfile edits. The patched rustix declares Rust 1.65;
the application's Rust 1.89 minimum remains unchanged. Native Windows gates
and the hosted Linux/MSRV matrix cover the resulting graph.

Fresh `cargo audit --json` returned exit code 0 with zero vulnerability entries
against RustSec database commit `55e1c3dfbd834237a05bbbf7b50ba3b5be27b662`
(1,555 advisories, updated 2026-11-21). Six existing notices remain visible:
unmaintained proc-macro-error, ttf-parser, zbus_names, zvariant and
zvariant_derive, plus the glib unsoundness notice on an inactive optional
Windows dependency path. Their previously documented reachability and upgrade
limits remain in the [release dependency review](RELEASE-0.8.0.md#dependency-review).
Known-advisory scanning does not establish that dependencies are defect-free.

The host is x86_64 Windows, using Rust/Cargo 1.100. The explicit Windows-target
gates therefore check the same operating-system configuration as the host;
Linux and Rust 1.89 results require the hosted matrix. The eight added tests
cover clipboard event/manual-read policy, bounded native payloads, destination
ancestor lookup, image retry and decode limits, removed subscription results,
malformed playlist URLs and cancellation history. Existing archive and capped
preset tests were strengthened. No test was ignored or filtered.

The native run used a private portable profile with monitoring, subscriptions,
startup changes and downloader discovery disabled. It verified an actual
close-to-tray hidden root restored by OS `WM_HOTKEY` dispatch, a second launch
exiting 0 and opening the primary's download popup, and normal primary exit 0.
The separate `native_intent` two-process example exercised the actual platform
receiver and asserted the exact URL string plus sender exit 0. The popup UIA
provider returned no nodes, so exact URL text in the GUI remains unverified;
the exact payload assertion comes from the platform receiver fixture. Earlier
failed/blocked harness attempts are retained separately and are not counted as
passing. No external download was attempted.

Reproduce with `cargo build --locked --example native_intent` followed by
`tools/Test-NativeRecovery.ps1 -AppPath <owned-app> -IntentFixturePath <owned-example>
-Destination <new-private-directory> -AllowTrustedExecution`. The script refuses
existing destinations and existing app/session identities and bounds owned
process waits. It must not be pointed at a user's active app/profile.

No external-site download, installer execution on the user's machine, physical
hotkey press, OS sign-in, physical mixed-DPI monitor change, or accessibility
certification is claimed. Existing release qualification remains scoped to its
recorded candidate; this audit does not publish a release.
